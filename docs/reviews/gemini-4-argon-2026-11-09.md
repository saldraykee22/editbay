## Pre-Release Audit Verdict: **NO-GO (Block Release)**

Editbay has a clean monorepo structure and a well-conceived command-based architecture, but **it is not ready for public release**. The audit uncovered **9 P0** and **15 P1** issues across the stack that break core user workflows, compromise local security, or cause silent data loss:

1. **Data loss in the desktop app**: `Ctrl+S` triggers video MP4 export instead of saving the project; opening an existing `.editbay.json` file or using "Save As" never writes subsequent edits back to that file; and clicking "New" silently overwrites `projects/current.json` within 700 ms.
2. **Broken timeline & export invariants**: `packages/core` ignores transition overlap in all duration/start-time calculations while `packages/engine` subtracts `transitionOut.durationMs`, causing progressive audio/text/preview desync after every transition. Non-default clip scaling runs `scale` before `format=rgba`, crashing FFmpeg whenever `iw*scale` or `ih*scale` lands on an odd pixel on `yuv420p` inputs.
3. **Security & trust boundaries**: `editbay-media://` serves any file on the host disk without an asset allowlist; IPC `project:save` writes arbitrary strings to arbitrary paths; `secrets:get` returns decrypted API keys to the renderer (and silently stores plaintext keys on disk when OS encryption is unavailable); and "Confirm edits" (`autoApply: false`) is bypassed because `apply_commands` remains exposed and unrestricted to the LLM.
4. **Distribution & licensing contradiction**: `packages/engine` hardcodes `-c:v libx264` (GPLv2) while `docs/licensing.md` mandates shipping an LGPL `--disable-gpl` FFmpeg build, and the packaged desktop build fails to bundle either FFmpeg or a working path to its bundled IBM Plex Sans font.

### 1. Fix Desktop Project Save, Autosave, and "New Project" Data Loss (**F-01**)

Any user who opens an existing project file or uses "Save As" and then continues editing expects their file (or `Ctrl+S`) to save their work. Instead, `Ctrl+S` pops up the MP4 video export dialog, `window.editbay.saveProject` is dead code, edits only ever go to `projects/current.json`, and clicking "New" overwrites `projects/current.json` 700 ms later with an empty project.

### 2. Unify Sequential Timeline Math Across `@editbay/core`, `@editbay/engine`, `@editbay/mcp`, and Desktop Preview (**F-02**, **F-10**, **F-11**)
- **Why now:** As soon as a user or AI agent adds a single video transition (`add_transition`), `@editbay/core` (`timeline.ts`), the AI system prompt (`prompt.ts`), the MCP server (`shared.ts`), and the desktop canvas preview (`compositor.ts`) disagree with the FFmpeg render engine (`timing.ts`) on every subsequent clip's start timestamp and total project duration. Worse, deleting or trimming a clip near a transition leaves the project in a state that fails `validateProject()`.

### 3. Fix FFmpeg Filtergraph Crashes (`scale` before `format=rgba` & Audio Stream Checks) and LGPL/GPL Encoder Mismatch (**F-03**, **F-04**, **F-08**, **F-09**)
- **Why now:** Export is the core deliverable of a video editor. Right now, scaling any `yuv420p` clip to an odd pixel dimension crashes FFmpeg (`width/height not divisible by 2`), placing a silent video clip on an audio track crashes FFmpeg (`Stream specifier ':a' matches no streams`), bundled fonts fail to resolve in packaged builds, and the hardcoded `-c:v libx264` encoder is incompatible with the LGPL FFmpeg build required by `docs/licensing.md`.

### 4. Enforce Proposal Mode (`autoApply: false`) and Lock Down Electron IPC & `editbay-media://` (**F-05**, **F-06**)
- **Why now:** The UI offers a "Confirm edits" safety mode (`autoApply: false`), but because `apply_commands` is still passed as an active tool and executes unconditionally in `executeTool`, tool-calling LLMs mutate the timeline without user consent. Combined with prompt injection via unescaped media filenames in the system prompt (**F-19**) and unrestricted file read/write in `editbay-media://` and `project:save` IPC (**F-06**), an untrusted project or media filename can read or overwrite arbitrary local files.

### 5. Replace the Three Divergent Desktop Front-Matter Parsers and Connect `brandId` (**F-07**)
- **Why now:** The Brand Panel and Skills/Memory UI in `apps/desktop` look functional on the surface, but `project.brandId` is never set (so the agent never receives the brand kit during desktop chat), and `frontmatter.ts` strips hex color codes after `#` as YAML comments when reading files written by `BrandPanel.tsx`. Consolidating onto `@editbay/harness`'s `FileMemoryStore` and `FileSkillStore` via main-process IPC fixes brand persistence, hex color corruption, and markdown heading duplication in one stroke.
